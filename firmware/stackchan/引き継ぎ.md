## 1. 何を作るか

ハッカソン向けの **空中にいる白い丸いおばけロボット**。  
図: [reference/content.png](reference/content.png)  
そばにいて見守り・会話・軽い物渡し。呼びかけ **「おばけちゃん」**。

- **脳・顔・耳・口・距離・移動指示** … このリポ（CoreS3）
- **天井移動のアクチュエータ** … 別担当・別マイコン

ベースは Stack-chan だが、今後は **おばけ専用に独自改造**していく。

## 2.1 双方向トランシーバ（v0.5.4 計画）

ユーザー／Next.js 側の必須モデル。**エンドポイントは端末待ち受けのまま**:

`ws://<stackchan-ip|:8765>/ws/v1/robot`（または `obake.local`）双方向。

### 役割イメージ

```
Next.js / 外部サーバ  ←──WS──→  Stack-chan（端末サーバ :8765）
  指令・下り音声・ウェイク          上行 PCM/JPEG・ack/error
  （将来はトランシーバ中継）         マイク→サーバ / サーバ→スピーカ
```

- **ウェイク**: 端末 Multinet だけに頼らず、**外部サーバ信号**でも起こす。受信したら既存の Stack-chan **ウェイク LED** 経路を点灯（新規 LED ドライバは作らない）。
- **音声**: 端末マイクをサーバへストリーム（上行）。サーバ音声を端末スピーカで再生（下行・フルデュプレックス／PTT 風）。
- **カメラ**: 同じサーバ関係のメディア経路（当面は one-shot `camera.capture` → JPEG）。
- **hand.set**: グリッパではない。サーバ信号で **首 yaw（x 軸回転）の open/close 2 パターン**（角度は `obake_config.h` の定数で手動調整）。LED ウェイクとは別コマンドだが、**「サーバ信号→端末アクチュエータ」**という型は同じ。

### メッセージ契約（目標）

| 方向 | type | 意味 |
|------|------|------|
| Next → 端末 | `hand.set` | open/close → **yaw 2 パターン**（度数は config）。実装予定: `obake_robot_ws` の handler + `ServoRequestSetHeadAngles` |
| Next → 端末 | `audio.start` / `audio.stop` | マイク上行の開始／停止 |
| Next → 端末 | `camera.capture` | 静止画 1 枚 |
| Next → 端末 | （将来）ウェイク信号 | 種別未確定 → LED 点灯 |
| Next → 端末 | （将来）スピーカ下行 | PCM／チャンク再生 |
| 端末 → Next | `audio.chunk` | マイク PCM（SDK は JSON+base64 想定。現行ファームは bin `0x01`+PCM） |
| 端末 → Next | `camera.frame` | JPEG（SDK は JSON+base64。現行は bin `0x02`+JPEG） |
| 端末 → Next | `ack` / `error` | 相関用。SDK は `request_id` 必須寄り |

ElectricSheep `packages/devices`（`createStackchanClient`）は `{type, request_id, data}` の TEXT を正とする。現行 Obake ファームは TEXT の `ack`/`error` に **`request_id` 無し**・メディアは **バイナリ**。ブリッジ／アダプタかファーム寄せが必要（フェーズ D）。

### ギャップ表（今 vs 不足）

| 項目 | 今（v0.5.3） | 不足・ずれ |
|------|----------------|------------|
| 端点 | 端末サーバ `8765/ws/v1/robot`・`hello`・同時 1 接続 | 安定化（DRAM/httpd）は別エージェント作業中 |
| `hand.set` | **yaw open/close 実装済み**（`kHandOpenYawDeg` 等 + handler）。グリッパではない | SDK 側は deprecated/unsupported のまま → フェーズ D で再有効化。度数は手動チューニング |
| `head.set` | SDK にある。サーボ API（`obake_servo_api`）はある | **WS handler 未配線** |
| `audio.start/stop` | 上行 tee マイク ON/OFF + ack | 下行（スピーカ再生）無し |
| `audio.chunk` | bin `0x01`+PCM16 | SDK 期待の JSON `audio.chunk`+`request_id` と不一致 |
| `camera.capture` / frame | one-shot。ack 後 bin `0x02`+JPEG | 連続フレーム無し。JSON `camera.frame`+`request_id` 無し |
| ウェイク→LED | 端末 Multinet／SimpleVox 計画 | **サーバ信号の type 未定義**。既存 LED フック未接続 |
| スピーカ下行 | 無し | フルデュプレックス未着手（メモリ逼迫と競合しやすい） |
| `request_id` / auth | ファームは `cmd` 文字列中心 | SDK は `request_id` 相関。**認証ヘッダは未仕様** |
| チーム鏡 | ElectricSheep `firmware/stackchan` へ後で PR | monorepo を潰さない。`packages/devices` は合意後に別 PR |

### 推奨フェーズ

| 段 | 内容 | 方針 |
|----|------|------|
| **A** | メモリ／ホームスワイプ安定 + `camera.frame` one-shot 信頼性 | **今の優先**。大きな cpp 変更はメモリ担当と衝突させない |
| **B** | 音声デュプレックス（まず下行スタブ→再生） | メモリ余裕後。上行は既存 tee を活かす |
| **C** | サーバウェイク信号 → 既存ウェイク LED | type 合意後。Multinet と並存 |
| **D** | Next.js SDK 整合（`request_id`・JSON frame/chunk or ブリッジ） | ElectricSheep `packages/devices` と慎重に PR |
| **A'**（並行可） | `hand.set` → yaw open/close | `obake_config.h` の `kHandOpenYawDeg` 等は投入済み。handler は同ファイル薄い変更（メモリ担当と合流注意）。LED ウェイク（C）とは別コマンド |

実装メモ（hand）: 度数は既に `obake_config.h` の `kHandOpenYawDeg` / `kHandCloseYawDeg` / `kHandYawSpeed`。`HandleRobotJson` の `hand.set` で `ServoRequestSetHeadAngles`（pitch は現状維持）。フルデュプレックス本体はこのタスクでは入れない。

## 5. 今どこまで（v0.5.3 時点）

### できている（Media / 制御）

- **経路（既定）**: PC / Next.js が `ws://<STA IP>:8765/ws/v1/robot` または `ws://obake.local:8765/ws/v1/robot` へ接続
- **開始条件**: `OnXiaozhiUiReady` → `RobotWsStart()` のみ。`EnterCustomSession` では httpd を始めない
- **スタック方針（重要）**: `stackchan` / `obake_hw` は **内部 DRAM** スタック（`xTaskCreatePinnedToCore`）。SPIRAM スタックだと flash cache disable 時に `esp_task_stack_is_sane_cache_disabled` でパニック→ブートループ（`095611b` で修正・実機検証済）。**httpd / `obake_ws_srv` ブートストラップだけ** SPIRAM スタックを維持
- **DRAM / Media 緩和**: Wi-Fi 接続後に `kRobotWsPostWifiDelayMs`（6s）待ってから `httpd_start`。失敗は最大 3 回・バックオフ。`httpd_stop` で listen FD を返してから再試行。JPEG は SPIRAM 寄せ＋内部空き不足時は capture スキップ。`camera.capture` は httpd ハンドラ内でエンコードせず延期
- **ホーム復帰**: 下スワイプは LVGL ロック外で `LeaveCustomSession()`（Robot WS / PaHub 停止）してから warm reboot
- **プロトコル**: 接続時 `hello`。`camera.capture` のときだけ JPEG（`0x02`+本体、長さプレフィクス無し）。PCM は `audio.start` 後に tee マイク（`0x01`+PCM16）。`hand.set` は **首 yaw の open/close**（`kHandOpenYawDeg` / `kHandCloseYawDeg`。§2.1）
- **同時接続**: 1。`max_open_sockets=4`。サーブ中は `WIFI_PS_NONE`
- **フォールバック**: `kMediaListenAsServer=0` で旧クライアント（PC `server.py:8030`、4 バイト長＋ PCM `0x20`）
- **サーボ**: `kForceAllServosOff=false` + `obake_servo_api`。自動きょろきょろは modifyLock 抑制のまま。WS からの `head.set` は未配線（`hand.set` は yaw 経由で可動）
- **ビルド短縮**: `scripts/fast_build.ps1`。`fullclean` / 不要な `reconfigure` / `sdkconfig` 大規模変更は避ける
- おばけ顔 CUSTOM、assets **6MB**、Flash バックアップ、モノレポ化は継続

### 以前失敗したこと（v0.5.3 で再挑戦した緩和）

| 症状 | 原因 | v0.5.3 の緩和 |
|------|------|----------------|
| `esp_task_stack_is_sane_cache_disabled` ブートループ | `stackchan`/`obake_hw` を SPIRAM スタックにしていた | **内部 DRAM** スタックに戻す。httpd のみ SPIRAM 維持（`095611b`） |
| `httpd_start` `0xb008` `ESP_ERR_HTTPD_TASK` | CUSTOM/Xiaozhi 直後は内部 DRAM 不足 | httpd の SPIRAM `task_caps`、ready 後＋ Wi-Fi 後の遅延 |
| `listen (112)` | 失敗リトライで listen FD リーク | `httpd_stop`、最大 3 回、バックオフ、無限リトライ禁止 |
| CUSTOM 直後 Media で再起動 | Wi-Fi/Xiaozhi 前に重いネット | `EnterCustomSession` では開始しない |

## 6. 開発の始め方（別 PC）

別 PC で続けるときの手順。正本は常に GitHub `main`。**ビルドはサブ PC、実機への書き込みはメイン PC。**

### 6.1 初回セットアップ

1. clone（パスは任意。以下は例）:
   ```powershell
   git clone https://github.com/kazu-1234/Obake_device.git
   cd Obake_device
   git config core.hooksPath .githooks
   ```
2. **サブ PC だけ** ESP-IDF **v5.5.4** を Espressif IDF Manager（EIM）で入れる。ツールパス既定は `C:\Espressif\tools`
3. **メイン PC** は IDF 不要。`pip install esptool pyserial`。実機 USB はメインへ
4. **git に入らない依存**（サブ向け。どちらか一方）:
   - **推奨・速い**: 既にビルドできている PC から USB 等でコピー
     | コピー元（`firmware/`） | コピー先 |
     |-----------------------------------|----------|
     | `xiaozhi-esp32/` | `firmware/xiaozhi-esp32/` |
     | `managed_components/` | `firmware/managed_components/` |
     | `dependencies.lock`（あれば） | `firmware/dependencies.lock` |
     | `sdkconfig.defaults.local` | `firmware/sdkconfig.defaults.local` |
   - **代替**: `firmware/` で `python fetch_repos.py`（`xiaozhi-esp32` 取得＋パッチ）。その後 IDF 環境で一度 `idf.py build` して `managed_components` を解決
5. `sdkconfig.defaults.local` は **秘密・端末固有**（Wi-Fi / ウェイク等）。git 禁止。無いとビルドは通ることがあるが、本番と同じ挙動にならない。必ず手渡しコピー
6. Flash 前バックアップは [バックアップと戻し方.md](バックアップと戻し方.md)

### 6.3 build / flash（サブ → メイン）

**main 現状（参考）**: Robot WS **端末サーバ**（v0.5.3）＋ CUSTOM 中の下スワイプホーム修正済み（例: `0bffac6` Media サーバ、`ff44ce3` スワイプ）。

**既定: サブでビルド、メインで書く**

サブ PC:

```powershell
cd C:\Users\kazuh\Documents\Arduino\Obake_device
git pull origin main
.\scripts\fast_build.ps1
.\scripts\export_flash_bundle.ps1 -Zip
```

`dist\obake_flash_bundle\` と `dist\obake_flash_bundle.zip` ができる。zip をメインへ渡す（USB・共有フォルダなど）。`firmware/build` 丸ごとは重いので渡さない。

メイン PC:

1. `git pull origin main`（手順・GUI の更新を取る）
2. zip を `Obake_device\dist\obake_flash_bundle\` に展開（中に `flasher_args.json` があること）
3. シリアルモニタを閉じ、COM を確認
4. 次のどちらか:

```powershell
cd C:\Users\kazuh\Documents\Arduino\Obake_device
.\scripts\flash_bundle.ps1 -Port COM3
```

または [tools/obake_flash_gui.pyw](tools/obake_flash_gui.pyw) → おばけちゃん FW → `dist\obake_flash_bundle` を選ぶ。

```

idf.py -p COM3 flash
```

COM / 注意:

- ポートは毎回確認（以前 **COM3**。別 PC では変わる）
- Arduino / `idf.py monitor` / シリアルモニタは **閉じてから** flash
- `fullclean` / 不要な `reconfigure` / `sdkconfig` 大規模変更は避ける（再コンパイルが極端に重い）
- Multinet 入り assets ≈ 5.5MB → `partitions.csv` の assets は **6MB 必須**
- `kObakeAutoCustom=1` なら起動後 CUSTOM 自動。手動ならランチャー **CUSTOM**
