## 1. 何を作るか

ハッカソン向けの **空中にいる白い丸いおばけロボット**。  
図: [reference/content.png](reference/content.png)  
そばにいて見守り・会話・軽い物渡し。呼びかけ **「おばけちゃん」**。

- **脳・顔・耳・口・距離・移動指示** … このリポ（CoreS3）
- **天井移動のアクチュエータ** … 別担当・別マイコン

ベースは Stack-chan だが、今後は **おばけ専用に独自改造**していく。

## 4. ハード

Port.A → PaHub v2.1（0x70）

| CH | 接続 |
|----|------|
| 0 | 左目 OLED（Grove–Dupont） |
| 1 | 右目 OLED |
| 2 | ToF U010（床向き） |

- Port.A I2C: **SDA=GPIO2 / SCL=GPIO1 / port 0**（内蔵バスと分離）。AW9523 **BUS_OUT_EN** を CUSTOM 開始時に再アサート
- OLED: SH1106 系。列オフセット 2、132 列白埋め
- ToF: Long Range、表示上限 200 cm
- 詳細部品・配線色: [README.md](README.md)

## 5. 今どこまで（v0.5.3 時点）

### できている（Media / 制御）

- **経路（既定）**: PC / Next.js が `ws://<STA IP>:8765/ws/v1/robot` または `ws://obake.local:8765/ws/v1/robot` へ接続
- **開始条件**: `OnXiaozhiUiReady` → `RobotWsStart()` のみ。`EnterCustomSession` では httpd を始めない
- **DRAM 対策**: ブートストラップ／httpd タスクは SPIRAM スタック。Wi-Fi 接続後に `kRobotWsPostWifiDelayMs`（6s）待ってから `httpd_start`。失敗は最大 3 回・バックオフ。`httpd_stop` で listen FD を返してから再試行（`listen (112)` の無限ループをしない）
- **プロトコル**: 接続時 `hello`。`camera.capture` のときだけ JPEG（`0x02`+本体、長さプレフィクス無し）。PCM は `audio.start` 後に tee マイク（`0x01`+PCM16）。`hand.set` は ack のみ
- **同時接続**: 1。`max_open_sockets=4`。サーブ中は `WIFI_PS_NONE`
- **フォールバック**: `kMediaListenAsServer=0` で旧クライアント（PC `server.py:8030`、4 バイト長＋ PCM `0x20`）
- **サーボ**: `kForceAllServosOff=false` + `obake_servo_api`。自動きょろきょろは modifyLock 抑制のまま
- **ビルド短縮**: `scripts/fast_build.ps1`。`fullclean` / 不要な `reconfigure` / `sdkconfig` 大規模変更は避ける
- おばけ顔 CUSTOM、assets **6MB**、Flash バックアップ、モノレポ化は継続

### 以前失敗したこと（v0.5.3 で再挑戦した緩和）

| 症状 | 原因 | v0.5.3 の緩和 |
|------|------|----------------|
| `httpd_start` `0xb008` `ESP_ERR_HTTPD_TASK` | CUSTOM/Xiaozhi 直後は内部 DRAM 不足 | SPIRAM `task_caps`、ready 後＋ Wi-Fi 後の遅延 |
| `listen (112)` | 失敗リトライで listen FD リーク | `httpd_stop`、最大 3 回、バックオフ、無限リトライ禁止 |
| CUSTOM 直後 Media で再起動 | Wi-Fi/Xiaozhi 前に重いネット | `EnterCustomSession` では開始しない |

## 6. 開発の始め方（別 PC）

別 PC でビルドするときの手順。正本は常に GitHub `main`。

### 6.1 初回セットアップ

1. clone（パスは任意。以下は例）:
   ```powershell
   git clone https://github.com/kazu-1234/Obake_device.git
   cd Obake_device
   git config core.hooksPath .githooks
   ```
2. ESP-IDF **v5.5.4** を Espressif IDF Manager（EIM）で入れる。ツールパス既定は `C:\Espressif\tools`
3. **git に入らない依存**を用意する（どちらか一方）:
   - **推奨・速い**: 既にビルドできている PC から USB 等でコピー
     | コピー元（この PC の `firmware/`） | コピー先 |
     |-----------------------------------|----------|
     | `xiaozhi-esp32/` | `firmware/xiaozhi-esp32/` |
     | `managed_components/` | `firmware/managed_components/` |
     | `dependencies.lock`（あれば） | `firmware/dependencies.lock` |
     | `sdkconfig.defaults.local` | `firmware/sdkconfig.defaults.local` |
   - **代替**: `firmware/` で `python fetch_repos.py`（`xiaozhi-esp32` 取得＋パッチ）。その後 IDF 環境で一度 `idf.py build` して `managed_components` を解決
4. `sdkconfig.defaults.local` は **秘密・端末固有**（Wi-Fi / ウェイク等）。git 禁止。無いとビルドは通ることがあるが、本番と同じ挙動にならない。必ず手渡しコピー
5. Flash 前バックアップは [バックアップと戻し方.md](バックアップと戻し方.md)

### 6.2 毎回の同期（必須）

| タイミング | やること |
|------------|----------|
| **作業前** | `git pull origin main`（別 PC と同時作業のため） |
| **作業単位のあと** | `git add` → `git commit` → **`git push origin main`**（ローカルだけ残さない） |
| **絶対 push しない** | `version_history.txt` / `.env` / 鍵 / `sdkconfig.defaults.local` / `latest.jpg` / `build/` |

```powershell
cd <Obake_device>
git pull origin main
# …編集…
git status   # 秘密・version_history が載っていないか確認
git add <変更ファイル>
git commit -m "短い why"
git push origin main
```

- Author は `kazu` / GitHub noreply。Cursor trailer / `Co-authored-by` 禁止（`.githooks`）
- 旧 `Documents\Arduino\Stackchan` は正本にしない

### 6.3 build / flash

**main 現状（参考）**: Robot WS **端末サーバ**（v0.5.3）＋ CUSTOM 中の下スワイプホーム修正済み（例: `0bffac6` Media サーバ、`ff44ce3` スワイプ）。

推奨（増分・ccache）:

```powershell
cd <Obake_device>
powershell -ExecutionPolicy Bypass -File .\scripts\fast_build.ps1
# 書き込みもするとき（ポートは毎回確認）:
powershell -ExecutionPolicy Bypass -File .\scripts\fast_build.ps1 -Flash -Port COM3
```

従来:

```powershell
$env:IDF_TOOLS_PATH = "C:\Espressif\tools"
. "C:\Espressif\tools\Microsoft.v5.5.4.PowerShell_profile.ps1"
Set-Location "<Obake_device>\firmware"
idf.py build
idf.py -p COM3 flash
```

COM / 注意:

- ポートは毎回確認（この PC では以前 **COM3**。別 PC では変わる）
- Arduino / `idf.py monitor` / シリアルモニタは **閉じてから** flash
- `fullclean` / 不要な `reconfigure` / `sdkconfig` 大規模変更は避ける（再コンパイルが極端に重い）
- Multinet 入り assets ≈ 5.5MB → `partitions.csv` の assets は **6MB 必須**
- `kObakeAutoCustom=1` なら起動後 CUSTOM 自動。手動ならランチャー **CUSTOM**

Media 確認（既定＝端末サーバ `kMediaListenAsServer=1`）:

```powershell
python homelab\obake_media\client_test.py obake.local
# または STA IP: python homelab\obake_media\client_test.py 172.16.0.xx
```

フォールバック（`kMediaListenAsServer=0` のときだけ）: `python server.py` → `http://127.0.0.1:8030/obake/latest.jpg`

Flash GUI: [tools/obake_flash_gui.pyw](tools/obake_flash_gui.pyw)

### 6.4 チーム共有（ElectricSheep-100bus）への出し方

ハッカソン monorepo 側の Stack-chan 正本パスは次のみ:

`https://github.com/Tebaeleven/ElectricSheep-100bus/tree/develop/firmware/stackchan`

**関係**: `Obake_device`（private）で固めた差分を、ElectricSheep の **`firmware/stackchan/` だけ**に手動同期して PR する（submodule ではない。Next.js / `packages/` / 他ファームは触らない）。

```powershell
# 1) 作業用 private を最新に
cd C:\Users\kazuh\Documents\Arduino\Obake_device
git pull origin main

# 2) チーム monorepo（別ディレクトリ。Obake_device を上書きしない）
cd C:\Users\kazuh\Documents\Arduino\ElectricSheep-100bus
git fetch origin
git checkout develop
git pull origin develop
git checkout -b feat/stackchan-<短い内容>

# 3) Obake_device → firmware/stackchan/ へ必要な差分だけコピー
#    入れない: sdkconfig.defaults.local / version_history の秘密拡大 /
#              latest.jpg / build_log / reference/content.png / Wi-Fi・API 鍵
#    packages/devices や Next.js は、合意なしに壊さない（必要なら別 PR）

# 4) PR は必ず develop 向け（main 直 push・force push 禁止）
git add firmware/stackchan
git commit -m "feat(stackchan): <why>"
git push -u origin HEAD
gh pr create --base develop --title "..." --body "..."
```

- クローン例: `Documents\Arduino\ElectricSheep-100bus`（`Obake_device` の隣）
- 競合・相手側の方が新しいときは上書きせず、差分を報告して判断を仰ぐ
- 親の `firmware/README.md` や SDK 文言が古いままなら、別 PR で直す
