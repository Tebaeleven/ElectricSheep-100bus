## 1. 何を作るか

ハッカソン向けの **空中にいる白い丸いおばけロボット**。  
図: [reference/content.png](reference/content.png)  
そばにいて見守り・会話・軽い物渡し。呼びかけ **「おばけちゃん」**。

- **脳・顔・耳・口・距離・移動指示** … このリポ（CoreS3）
- **天井移動のアクチュエータ** … 別担当・別マイコン

ベースは Stack-chan だが、今後は **おばけ専用に独自改造**していく。

## 4. ハード

Port.A → PaHub v2.1（0x70）

| CH | 接続 |
|----|------|
| 0 | 左目 OLED（Grove–Dupont） |
| 1 | 右目 OLED |
| 2 | ToF U010（床向き） |

- Port.A I2C: **SDA=GPIO2 / SCL=GPIO1 / port 0**（内蔵バスと分離）。AW9523 **BUS_OUT_EN** を CUSTOM 開始時に再アサート
- OLED: SH1106 系。列オフセット 2、132 列白埋め
- ToF: Long Range、表示上限 200 cm
- 詳細部品・配線色: [README.md](README.md)

## 5. 今どこまで（v0.5.2 時点・このチャットまとめ）

### できている（Media / 制御）

- **経路**: `Stack-chan -- Wi-Fi(STA) -- PC`（USB は flash／シリアルのみ。映像音声は USB ではない）
- **現行方式（クライアント）**: 端末が PC の `ws://…:8030/obake/media` へ外向き接続し JPEG（`0x02`）+ PCM（`0x20`）を上行
- **PC サーバ**: `homelab/obake_media/server.py`（`0.0.0.0:8030`）
- **AI／画面の共通取り出し**: `http://127.0.0.1:8030/obake/latest.jpg` のみ（旧 `/obake/view` はリダイレクト）。状態は `/obake/status`
- **マイク**: 実パケット受信確認済み。表示は **再生ではなく PCM RMS（音量）**（`last_pcm_rms` / `pcm_count`）
- **マイク二重読取対策**: Xiaozhi `AudioService` の Read を tee して Media 上行（直 `InputData` すると RMS=0 になりやすい）
- **送り先設定**（`obake_config.h`）:
  - `kMediaWsHost` = `obake.media.stackchan`（ログ用論理名）
  - `kMediaWsLanIp` = PC の Wi‑Fi IPv4（例 `172.16.0.66`）← **ESP の実 TCP 先**
  - `kMediaWsPort` / `kMediaWsPath` / 画質 `kMediaJpegQuality` / 間隔 `kMediaJpegIntervalMs`
- **名前解決注意**: Windows `hosts` は **PC ブラウザ専用**。ESP は hosts を見ない → ファームの `kMediaWsLanIp`（または LAN DNS）が必要
- **CUSTOM 自動起動**: `kObakeAutoCustom`（`1`=自動 / `0`=手動）※ `app_launcher.cpp`
- **サーボ**: `kForceAllServosOff=false` + `obake_servo_api`（サーバ／API 指令用）。自動きょろきょろは modifyLock 抑制のまま
- **ビルド短縮**: `scripts/fast_build.ps1`（ccache・jobs=8）。`fullclean` / 不要な `reconfigure` / `sdkconfig` 大規模変更は避ける（2400 ステップ級）
- おばけ顔 CUSTOM（口・両目・ToF）、assets **6MB**、Flash バックアップ手順、モノレポ化は継続

### 試して失敗した方式（端末＝サーバ）※次チャット再挑戦の前提

やりたかったこと: **PC／ブラウザが Stack-chan のアドレスにアクセスして映像を取る**（端末が `esp_http_server` で待ち受け）。

試したこと（概略）:

1. `obake_robot_ws` を **WS サーバ**化（例: ポート **8765**、パス `/ws/v1/robot`）
2. CUSTOM 起動後に `httpd_start` → PC から `client_test.py` 等で接続予定

うまくいかなかった理由（実ログ）:

| 症状 | 原因の見立て |
|------|----------------|
| `httpd_start failed err=0xb008`（`ESP_ERR_HTTPD_TASK`） | CUSTOM／Xiaozhi 起動直後は **内部 DRAM が逼迫**し、httpd タスク生成に失敗しやすい |
| 続けて `httpd_server_init: error in listen (112)` | 失敗リトライで **listen FD／ソケットがリーク／枯渇**しやすい（heap 全体は空いていても失敗が続く） |
| 端末 IP が都度変わる | DHCP。PC から安定 URL にしづらい（mDNS／固定 IP／ホスト名が別途必要） |
| （関連）Media を CUSTOM 直後に起動すると再起動 | Wi‑Fi／Xiaozhi ready 前に重いネット処理を始めると不安定 → **遅延起動が必要**だった |

途中で試した緩和（サーバ方式では未完了のまま方針転換）:

- httpd / 補助タスクのスタックを **SPIRAM** に載せる
- `max_open_sockets` 縮小、起動遅延、リトライ回数制限
- LWIP ソケット数の見直し

その後、安定優先で **端末クライアント → PC サーバ（現行 v0.5.2）** に切り替え、JPEG/PCM 上行・`latest.jpg`・RMS まで実機確認済み。

## 6. 開発の始め方（別 PC）

1. clone: `git clone https://github.com/kazu-1234/Obake_device.git`
2. ESP-IDF **v5.5.4**（EIM）を入れる
3. `firmware/` で依存取得（`managed_components` / `xiaozhi-esp32` は git 外。初回は既存マシンからコピー可）
4. 必要なら [バックアップと戻し方.md](バックアップと戻し方.md) で本体を復元
5. 下の手順で build / flash
6. `kObakeAutoCustom=1` なら起動後 CUSTOM 自動。手動ならランチャー **CUSTOM**

### build / flash

推奨（遅い PC）:

```powershell
cd C:\Users\kazuh\Documents\Arduino\Obake_device
.\scripts\fast_build.ps1 -Flash
```

従来:

```powershell
$env:IDF_TOOLS_PATH = "C:\Espressif\tools"
. "C:\Espressif\tools\Microsoft.v5.5.4.PowerShell_profile.ps1"
Set-Location "C:\Users\kazuh\Documents\Arduino\Obake_device\firmware"
idf.py build
idf.py -p COM3 flash
```

- ポートは毎回確認（以前は COM3）
- シリアルモニタは閉じる
- Multinet 入り assets ≈ 5.5MB → `partitions.csv` の assets は **6MB 必須**
- PC Media サーバ: `cd homelab\obake_media` → `python server.py` → `http://127.0.0.1:8030/obake/latest.jpg`

Flash GUI: [tools/obake_flash_gui.pyw](tools/obake_flash_gui.pyw)

## 7. 次にやること（優先）

### 次チャットの主目的（再挑戦）

**端末を再び Media／映像のサーバにし、PC から Stack-chan のアドレスへアクセスして映像（と必要なら音声）を取る方式を再トライする。**

再トライ時に必ず踏まえること:

1. **内部 DRAM**: httpd タスクは SPIRAM スタック／遅延起動（Xiaozhi UI ready・Wi‑Fi 接続後）を前提に設計する
2. **listen 失敗後の FD リーク**: 失敗時はソケットを確実に閉じる／リトライしすぎない／必要なら再起動で回復
3. **到達 URL**: 端末 DHCP IP ではなく mDNS（例 `.local`）や表示用ホスト名、または設定で固定しやすくする
4. **Xiaozhi 同居**: カメラ／マイクは AudioService tee や既存キャプチャ経路と競合させない
5. **現行クライアント方式はフォールバックとして残せる**ように境界を分ける（切替定数推奨）
6. PC 側は「端末 URL を開く／AI が端末から読む」形に合わせる（いまの `server.py` 受信口とは役割が逆）

### その他（後回し可）

1. 「おばけちゃん」ウェイクを確実に（SimpleVox 推奨）
2. 表情を Stack-chan の動きに連動
