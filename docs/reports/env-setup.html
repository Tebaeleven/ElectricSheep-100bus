上から順に着手するのが最短。チェックを入れながら進める。

  • 担当: 開発者所要 1 分

    なぜ人間か: 別セッションが作った worktree なので、エージェントは他セッションの作業中ディレクトリを消せない規約（削除は作成者のみ）。中身はすでに develop にマージ済み。

    git -C <REPO_ROOT> worktree remove <REPO_ROOT>/.claude/worktrees/bootstrap
  • 担当: あなた（対人）最優先・ブロッカー

    なぜ人間か: 相手チームとのコミュニケーションが必要で、回答が来るまで実機接続（項目 3）が始められないため。聞く項目は下記の 7 点＋詳細版チェックリスト。

    聞くことなぜ必要か
    IP アドレス（3 台）RAIL_BASE_URL / DESKTOP_BASE_URL / STACKCHAN_WS_URL に入れる。DHCP か固定か、mDNS 名があるかも
    ポート（3 台）同上。SDK 既定はモックの 8791 / 8792 / 8793
    認証現状は DEVICE_AUTH_TOKEN → Authorization: Bearer の暫定実装。別ヘッダ・クエリ・mTLS なら SDK 修正が必要
    軸方向axis の x / y / z が物理的にどの向きか、direction: 1 がどちら向きか。可動範囲・原点・リミットスイッチの有無。現在の instructions は「x=左右 / y=前後 / z=上下（仮）」
    速度duration_ms 500 で実際に何 cm 動くか。安全上限 3000ms は妥当か
    音声形式audio.chunk のコーデック・サンプリングレート・チャンネル数・1 チャンク長・seq の採番規則
    撮影ディスプレイマルチモニタ時にどれを撮るか、指定できるか。解像度・画像形式。browser/open はどのブラウザで開くか

    詳細版（ack / error のスキーマ、同時接続の可否、ネットワーク条件を含む 11 項目）： <REPO_ROOT>/docs/runbooks/devices.md の「§8 未確定事項チェックリスト」

  • 担当: 開発者（実機の前で）項目 2 の回答待ち

    なぜ人間か: 実機の電源投入・LAN 接続・物理的な安全確認（動いてよい状態か）が必要で、エージェントには機器の状態が見えないため。最初の rail/move は必ず人が機器を見ながら短時間（500ms）で試す。

    編集するファイル（このファイルだけ。コードは触らない）：

    <REPO_ROOT>/client/web/.env.local

DEVICE_MODE=real
RAIL_BASE_URL=http://192.168.x.x:ポート
DESKTOP_BASE_URL=http://192.168.x.x:ポート
STACKCHAN_WS_URL=ws://192.168.x.x:ポート
DEVICE_AUTH_TOKEN=（配布されたら）

    手順：① 機器を直接 curl（devices.md §4）→ ② pnpm dev 再起動 → ③ http://localhost:3000/dev で 1 エンドポイントずつ実行 → ④ チャットで「x 軸プラスに 500ms 動いて」。

    緊急停止は /dev 画面上部に常時固定されている（rail/stop / audio/stop）。
